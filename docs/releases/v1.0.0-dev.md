# Level 7 Dev Loop v1.0.0-dev — UNSIGNED (NO DEVELOPER ID), NOT NOTARIZED

> **Evaluation-only prerelease:** these binaries have no Apple Developer ID
> Application signature and were not submitted for Apple notarization. macOS
> Gatekeeper may block them. Formal support is `WITHHELD`, and actual
> provider/model execution is `NOT_RUN`.

This prerelease exposes the exact `1.0.0-dev` / `development-candidate`
packages for bounded evaluation without Apple release credentials. It is not
stable `v1.0.0`, does not satisfy the stable release gates, and does not
transfer evidence or authority to the separate stable release.

## Exact attached assets

Use only these four attached release assets:

- `level7-dev-loop-1.0.0-dev-codex.zip`
- `level7-dev-loop-1.0.0-dev-claude.zip`
- `SHA256SUMS`
- `UNSIGNED-PRERELEASE-MANIFEST.json`

GitHub-generated source ZIPs and tarballs are not installable Level 7
packages. `UNSIGNED-PRERELEASE-MANIFEST.json` binds the exact merged commit and
tree, workflow run and attempt, input and archive digests, release-note digest,
and the explicit unsigned, unnotarized, unsupported state. GitHub artifact
attestations cover all four attached assets; those attestations establish
workflow provenance and integrity, not Apple identity, notarization, provider
qualification, or support.

## Signature and macOS boundary

No `codesign --sign`, Developer ID identity, Apple Team ID, trusted signing
timestamp, or notarization submission was used. The preparation workflow
inspected four shared package inputs. Their exact manifest keys are:

- `darwin-arm64/l7`
- `darwin-arm64/l7-embed`
- `darwin-amd64/l7`
- `darwin-amd64/l7-embed`

Inside each ZIP, the corresponding files are under `bin/`. The manifest
records the exact observed state for every listed input as either `AD_HOC` or
`NONE`. An ad-hoc signature is not an Apple Developer ID signature and does
not establish publisher identity or Gatekeeper trust.

The packages contain the declared macOS arm64 and amd64 inventory, but only
offline validation applies to both architectures. At preparation time,
actual-host lifecycle is `NOT_RUN`; the manifest records this as
`actual_host_lifecycle_at_preparation:"NOT_RUN"`. No actual-host operation
occurs during artifact preparation. Publication is gated by one bounded Codex
lifecycle trial and one bounded Claude lifecycle trial on one honestly recorded
declared package architecture. The other architecture's actual-host lifecycle
remains `NOT_RUN`; provider/model execution remains `NOT_RUN` for both hosts;
formal support remains `WITHHELD`. The single run-bound JSON comment on the
merged prerelease-change pull request is the sole post-preparation host
evidence.

Gatekeeper may refuse to open these binaries. If it does, stop. Do not disable
Gatekeeper globally or treat an operating-system bypass as qualification. Wait
for the separate signed and notarized `v1.0.0` release, when available, if
normal macOS trust behavior is required.

## Verify before evaluation

Use a new disposable extraction root and verify the attached bytes before
extraction:

```sh
evaluation_root="$HOME/.local/share/level7/evaluations/v1.0.0-dev"
test ! -e "$evaluation_root"
mkdir -p "$evaluation_root/assets" "$evaluation_root/codex" "$evaluation_root/claude"

gh release download v1.0.0-dev \
  --repo addressanup/level7-dev-loop \
  --dir "$evaluation_root/assets"

(cd "$evaluation_root/assets" && shasum -a 256 -c SHA256SUMS)

candidate_commit=$(jq -er .candidate.commit \
  "$evaluation_root/assets/UNSIGNED-PRERELEASE-MANIFEST.json")
for asset in "$evaluation_root"/assets/*; do
  gh attestation verify "$asset" \
    --repo addressanup/level7-dev-loop \
    --signer-workflow addressanup/level7-dev-loop/.github/workflows/unsigned-prerelease.yml \
    --signer-digest "$candidate_commit" \
    --source-ref refs/heads/main \
    --source-digest "$candidate_commit"
done
```

Review `UNSIGNED-PRERELEASE-MANIFEST.json` and accept the unsigned boundary
before extracting either host package:

```sh
ditto -x -k \
  "$evaluation_root/assets/level7-dev-loop-1.0.0-dev-codex.zip" \
  "$evaluation_root/codex"

ditto -x -k \
  "$evaluation_root/assets/level7-dev-loop-1.0.0-dev-claude.zip" \
  "$evaluation_root/claude"
```

The extraction root is disposable, but the following marketplace and plugin
commands modify the current host's configured state. Do not install this
prerelease alongside an existing
`level7-dev-loop@level7-engineering-v1` installation. If that identity already
exists, stop rather than replacing or removing it during this evaluation.

For a bounded Codex evaluation:

```sh
codex plugin marketplace add "$evaluation_root/codex"
codex plugin add level7-dev-loop@level7-engineering-v1
```

For a bounded Claude Code evaluation:

```sh
claude plugin marketplace add "$evaluation_root/claude" --scope user
claude plugin install level7-dev-loop@level7-engineering-v1 --scope user
```

Installing the plugin does not qualify a provider or model. Stop on any
verification, Gatekeeper, installation, discovery, startup, removal, or
residue failure; do not retry until green or weaken a host or operating-system
control.

## Remove the evaluation

Remove the plugin before removing its marketplace:

Run only the command pair for the host evaluated. Do not run either pair
against a pre-existing installation.

```sh
codex plugin remove level7-dev-loop@level7-engineering-v1
codex plugin marketplace remove level7-engineering-v1

claude plugin uninstall level7-dev-loop@level7-engineering-v1 --scope user
claude plugin marketplace remove level7-engineering-v1 --scope user
```

Inspect for residue before moving the disposable extraction root to Trash.
Removal does not delete repositories, credentials, provider configuration, or
private `.git/l7` state.

## Stable boundary and rollback

At the `v1.0.0-dev` publication boundary, `v0.1.1` is the latest stable
release and the skills-only rollback. This prerelease is published with
`prerelease:true` and `make_latest:"false"`.

The separate `v1.0.0` release, when available, requires new Developer ID-signed
and Apple-notarized packages, new hashes, a stable manifest, exact-archive
provider trials, and a new asset-bound Product Owner decision. It will not
update, rename, overwrite, or promote these prerelease assets in place.
