## Retained release checks and limitations

The release retains exact squash lineage and tested tree identity; fresh
baseline/shadow, both macOS, paired benchmark and trusted-policy PR checks;
post-merge baseline/shadow and both macOS checks; reproducible unsigned inputs
and host packages; offline native CLI/MCP, upgrade, rollback, removal and
residue checks; exact artifact/source attestations; and immutable publication.

Only the real owner can authorize and dispatch this one-shot preparation and
publish its exact artifact through the existing forge login. Owner authority,
CI, main, artifact, annotated tag, draft, asset bytes, and immutable controls
are rechecked before publication. The workflow has no release-write
permission, no owner/admin token, and no signing or provider execution.
Existing protected environment settings are not changed.

Offline lifecycle checks are not actual Codex/Claude marketplace or provider
trials. macOS 13+ arm64/amd64 is the package target, not a formally qualified
support matrix. Missing observations do not transfer across host versions,
architectures, providers, models, configurations, or archives.

The public Codex comparison remains formative: 48 valid trials, both arms
24/24 correct, no observed safety violations, exact McNemar $p=1.0000$, and
improvement `INCONCLUSIVE`. Crew median time was 3m4s and 70 turns versus 55s
and 24 turns for plain Codex. Eight small Python tasks and 24 public pairs
establish neither equivalence nor protected release qualification. The owner
waived `L7-EVAL-007`; this release does not claim to satisfy it.

Level 7 is not a sandbox. Host permissions and credentials remain the
enforcement boundary. Optional gateway secrets are user-managed references,
never values stored in Level 7 policy.

changing the retained extraction root. Verify any replacement before install;
do not overwrite an existing root. Uninstall does not remove repositories,
credentials, provider configuration, or unrelated host state. Inspect private
`.git/l7` state separately.

remains the rollback. Remove v1 first, then use the tag-pinned

`v1.0.0-dev` prerelease remains unchanged. Never replace immutable assets or
move an existing tag; use a separately reviewed patch release.
