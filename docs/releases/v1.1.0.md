# Level 7 Dev Loop v1.1.0 — UNSIGNED, NOT NOTARIZED

This is the second owner-authorized **stable-channel** bundled release for
Codex and Claude Code. **Stable does not imply Apple trust or qualification.**
The owner explicitly waived all four release gates again for this version;
the v1.0.0 waivers did not carry over:

| Gate | Policy | Evidence |
|---|---|---|
| Apple Developer ID signing and notarization | WAIVED | NOT_RUN |
| Protected holdout release evaluation | WAIVED | NOT_RUN |
| Separate release operator and protected production approval | WAIVED | Owner-only publication; no separate approval |
| Exact-asset Codex and Claude provider trials | WAIVED | NOT_RUN |

**Formal support is WITHHELD.** macOS Gatekeeper may block the binaries.
Never disable Gatekeeper globally. Users who require Developer ID identity,
Apple notarization, or verified provider qualification should not install
this release. GitHub attestations and checksums establish byte integrity and
workflow provenance only; they do not replace the waived gates.

## What is new

- `l7 plugin install|update|status|rollback|uninstall`: a conventional,
  verified lifecycle for the plugin in both hosts, plus a reviewable one-time
  bootstrap script (`scripts/l7-bootstrap.sh`) that installs a verified `l7`
  into a user-owned prefix. Installs and updates bind the release manifest,
  `SHA256SUMS`, the host archive, and the extracted CLI by SHA-256 and GitHub
  artifact attestations (`gh attestation verify --bundle`, no GitHub login) to
  the release workflow, `refs/heads/main`, and the exact source commit before
  anything is executed or registered. Extractions are immutable versioned
  directories; the previous verified version is retained for an offline
  rollback; host registration changes run under a lock and a journal that
  restores the previous registration on failure. Stable is the default
  channel, and unsigned or withheld-support releases require
  `--accept-unsigned --accept-unqualified` every time.
- Everything shipped in v1.0.0 (17 skills, the native `l7` engine, local MCP
  bridge, embedding helper, default-OFF orchestration, private memory, Cyber,
  Headless, and the opt-in crew) is unchanged in behavior.

## Installable assets and verification

Use only these four attached assets:

- `level7-dev-loop-1.1.0-codex.zip`
- `level7-dev-loop-1.1.0-claude.zip`
- `SHA256SUMS`
- `RELEASE-MANIFEST.json`

GitHub-generated source ZIPs/tarballs are not installable v1 packages.
The manifest binds the exact merged commit/tree, preparation workflow/run,
owner waiver authorization, all four input and both archive digests,
checksums, and these notes. It records `unsigned-unnotarized-prepared`,
all four `WAIVED` gates, all unrun qualification as `NOT_RUN`, and support as
`WITHHELD`. GitHub artifact attestations cover all four assets.

The recommended path is the [bootstrap and `l7 plugin` recipe](https://github.com/addressanup/level7-dev-loop#install-level-7);
the [manual verification recipe](https://github.com/addressanup/level7-dev-loop#manual-verification-and-installation)
remains valid. Review and deliberately accept the unsigned/unqualified
boundary before installing. Stop on integrity or Gatekeeper failure.

## Retained release checks and limitations

The release retains exact squash lineage and tested tree identity; fresh
baseline/shadow, both macOS, paired benchmark and trusted-policy PR checks;
post-merge baseline/shadow and both macOS checks; reproducible unsigned inputs
and host packages; offline native CLI/MCP, upgrade, rollback, removal and
residue checks; exact artifact/source attestations; and immutable publication.

The installer was additionally exercised against the published v1.0.0 assets
in disposable, isolated host profiles (Codex CLI 0.162.1 and Claude Code
2.1.291 on macOS arm64: install, status, uninstall). That is a formative
check of the installer, not an exact-asset provider trial of this release;
provider/model execution remains `NOT_RUN`, and macOS 13+ arm64/amd64 is the
package target, not a formally qualified support matrix. Missing observations
do not transfer across host versions, architectures, providers, models,
configurations, or archives.

Level 7 is not a sandbox. Host permissions and credentials remain the
enforcement boundary. Optional gateway secrets are user-managed references,
never values stored in Level 7 policy.

## Update, uninstall, and rollback

`l7 plugin update --all --accept-unsigned --accept-unqualified` moves an
installation managed by the CLI to this release and keeps the previous
verified version for `l7 plugin rollback --host <host>`; `l7 plugin uninstall
--host <host> --yes` removes only Level 7's own registration and unreferenced
installation files. A hand-registered v1.0.0 marketplace is adopted by
`l7 plugin install` without deleting its extraction, or can be removed with
the host commands in the README. Uninstall does not remove repositories,
credentials, provider configuration, or unrelated host state. Inspect private
`.git/l7` state separately.

The immutable [v1.0.0 release](https://github.com/addressanup/level7-dev-loop/releases/tag/v1.0.0),
the `v1.0.0-dev` prerelease, and the
[v0.1.1 skills-only rollback](https://github.com/addressanup/level7-dev-loop/releases/tag/v0.1.1)
remain unchanged. Never replace immutable assets or move an existing tag; use a
separately reviewed release.
